# 科研平台工程验收 — 2026-10-20

## 本轮完成

用户要求完善工程框架并保留扩展性，同时支持滚动数据预测、接入数据流、持续预测、训练和监视。已交付统一 `online_ts.platform` 命令入口、可安装 Python 包、两类合成示例及 [平台使用说明](../../../docs/PLATFORM.md)。

研究工作流包含协议/输入/源码/环境身份冻结、依赖步骤、独立尝试目录、后台 worker 收据、确定失败的有限重试、未知执行停止、人工证据对账、成本汇总和产物 hash 核验。已完成步骤恢复时只核验，不重复执行；对账后的原 worker 被禁止再次启动。

流链路复用原 Engine/Store/模型生命周期。新增持久 v2 到达日志、幂等接入、冲突拒绝、固定快照分页、生产者示例、实时 runner 锁与心跳、只读状态/监视、预测原点游标及管理命令。后台训练期间保留当前模型服务。标签按到达、成熟和修订语义处理，未成熟修订撤回当前旧标签；停流后继续结算历史预测。监视摘要从持久窗口重建，恢复时保留退化触发状态。

生命周期库升级为 schema 9，使用可为空的修订值明确表示标签撤回。旧库拒绝打开并保留原样，由其冻结旧版本读取；无迁移、兼容分支或真实旧批次恢复。

保留以下过程失败与修复事实：

1. 工作流测试首次普通沙箱执行因 `os.link` 的 WinError 5 阻塞，未进入行为验收；获准沙箱外执行后 12 项通过。日志测试曾遇临时目录和回环网络权限问题，调整测试临时目录并获准回环执行后通过。
2. 首次流集成 3 项中 2 项失败，原因是测试在异步训练刚提交完成、Engine 尚未消费结果时提前结束等待；补一次消费 tick 后通过，未修改训练结果。
3. 静态审查定位并修复：人工对账后迟到 worker 可启动、未成熟修订留下旧标签、停流后标签无法结算、窗口与摘要分次提交导致恢复遗漏，以及重建时退化触发标志丢失。对应行为已纳入集成/工作流验证。
4. pip 的首次离线 wheel 封装因系统沙箱临时目录 PermissionError 失败；使用同一已安装 setuptools PEP 517 后端在工作区构建成功，没有下载依赖。

## 当前所处环节与下一步

工程已达到可运行、可复现的单机科研平台基础版本；当前未部署持续业务服务。数据源、模型、训练资源、Agent 策略和监测指标的接入位置与约束已写入文档，复用既有接口。

下一步接入具体业务 producer，冻结变量、采样频率、预测跨度、标签成熟/修订规则与训练/发布政策，再进行长时间运行和故障演练。高吞吐长期部署还需明确留存期和修订期，完成持久标签游标与归档；当前标签全历史查询及完整预测保留的开销随日志增长。仅绑定本机回环，未实现 Kafka/MQTT 原生连接器或外网认证。没有执行生产压力、多机或断电恢复验证。
