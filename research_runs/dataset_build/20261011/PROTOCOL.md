# 新基础数据建库协议：2026-10-11

用户要求从 `data` 新增原始数据中挑选并按现有标准建立一到两个数据集。本阶段仅整理原始测量、固定划分与验证身份，不开展训练、模型搜索、性能诊断或测试评分。

选用发送包 `share_20260727.zip` 内 `industrial_timeseries_eval_120_v0.7.0.zip`。内包 SHA256 必须等于既有 MetroPT3 manifest 的 `b0c2489d1103f224c55e070da956f00e7905d4389850f31f5d2a34f42227a940`。仅打开选定 raw 文件、来源元数据、署名文件与 SHA256SUMS；不提取或读取 `ground_truth/`、benchmark 答案、prepared 传感器衍生表或原始工况标签文件。

选择依据限于原始数据的格式、通道数量、序列边界与现有任务匹配程度，不依据预测效果或测试分布。SKAB 使用全部 35 个真实测量 CSV；UCI Hydraulic 使用包内全部 8 个可对齐的 1Hz/虚拟传感器文件。其余来源本阶段不建库：SCANIA 包缺运行时序读数；IMS 仅首末振动片段且为单通道；C-MAPSS 是模拟机组周期数据且原任务为 RUL，需另行约定任务与设备划分。

两组统一按原生时间/顺序展开，以总行数划分 `floor(N*0.7)`、`floor(N*0.2)`、剩余测试。SKAB 全局按真实 datetime、原文件名（ordinal）、零基源行排序；相同时间的独立实验记录保持各自身份，当前切点必须无跨分区相同时间。Hydraulic 按原周期行、周期内 0..59 秒位置展开，没有绝对时间或周期间时间间隔假设。此为未来顺序预测划分；没有宣称整设备/整实验/整周期独立留出。

保留每个源传感器数值的原始字符串与字段拼写。SKAB 用 source_file/source_row 标识原文件行；Hydraulic 用 cycle_id/sample_offset_seconds 标识原矩阵行列。来源元数据、时间、索引和标签不能作为传感器输入。原文件逐字节保存在 raw_sources，准备表仅做无损拼接、重排和索引添加，明确 `table_raw_bytes_preserved=false`。

不删样本、不补值、不拟合变换。所有分区只做必要的格式、数值有限性、顺序和身份检查；min/max/mean 仅在训练分区计算。测试不计算数据分布汇总或预测指标，不能参与选择方案。窗口长度尚未冻结；窗口必须同时满足分区与原序列边界，SKAB 另遵守相邻间断 >30s 断开，Hydraulic 禁止跨周期。具体后续协议要按原生采样频率明确预测时间尺度。

验收须对照上游每文件 SHA256/大小、全文件与全样本覆盖、每个数值字符串/源位置、7:2:1 行数、分区边界、序列内顺序、分区 CSV 哈希和仅训练统计。MetroPT3 三分区哈希和精确源文件重构均须通过，原 manifest/profile 在阶段前后哈希相同。PowerShell 7 + .NET 实现，不运行本地研究 Python。

代码、协议、报告、来源索引、成本和验收收据纳入现有 GitHub 仓库；选定原始文件与准备层数据打包为独立 Release 资产，排除整个发送包及 ground_truth，登记大小、SHA256 和对应提交。同步后核验远端与资产。同步失败保留本地产出及失败记录。
