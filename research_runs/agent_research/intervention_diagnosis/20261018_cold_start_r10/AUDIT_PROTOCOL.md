# 冷启动开发阶段结果验收补充冻结

本文件只补齐PROTOCOL.md已经要求的结果验收实现，不修改训练、提示词、预算、输入权限、动作或科学采用标准。真实训练和实验Agent调用仍为0；本补充在任何真实反馈出现前冻结。

入口scripts/audit_coldstart_trial.py，输入为原服务器r10运行根目录，以及已结束探索的决策档案目录。决策档案须含16个逐轮snapshots、完整calls原始事件/提示/schema/收据、parent_facts、trial_completed、final_recommendations及auditor_lock。运行根目录已有冻结代码、A/B/C、runs和queries。audit不训练、不调用LLM、不解析D；部署验收器与决策档案同样受当前服务器传输授权边界约束。

验收范围：

1. 核对训练源码和协议hash、所有模型资产大小/hash、所有完成/开始目录、最多51次完整训练和32次调用；真实训练数按跨组选择先后和配方identity重建，逻辑成本另记。
2. 同seed初始参数逐张量一致。全部已存500步网格checkpoint全B重新推理，评分及残差hash与记录完全一致；重新检查best和平局取早规则，再全C重算所选checkpoint。重复推理使用冻结前向路径，不称独立训练重放。
3. 每个网格checkpoint另选固定首/中/末三个B窗口，用逐通道float64 CPU线性层与显式25点均值独立前向。事前容差rtol=1e-5、atol=2e-6；合成370通道探针最大绝对误差3.416219e-7。此抽查不替代全B/C重算，也不声称检查了每一步Adam更新。
4. 从实际输入重新生成q、A归一参数、训练权重、B/C目标掩码和普通参考x；核对三seed的Y/Z/目标/补集/MAE以及均值。条件参考按本轨迹时间顺序重建，先预测再加入当前响应；诊断版本和累计信用独立重建。
5. 对每次LLM调用，除检查收据外直接审计原始事件是否有工具调用。实际提示中的父事实、q登记、历史和诊断账本必须与本轨迹前一个snapshot严格匹配；只允许当前轮已经获得的测量反馈。跨组物理复用信息不得出现在历史事实包。
6. 重建2/4/8节点推荐、护栏和平局处理，核对最终推荐封存hash。任何失败保留FAILED收据，不能自动重训练、重调用或改变阈值。

实现与8项合成检查见auditor_lock及result_auditor_unit_checks。前6项检查的旧收据单独保留；最后补充真实/逻辑训练复用记账检查后重新运行8项。当前没有真实运行资产，因此真实开发结果验收尚未执行；GPU、SSH和CLI端到端状态仍待授权后的真实运行检验。
